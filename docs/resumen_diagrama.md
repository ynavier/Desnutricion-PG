# Descripción del Diagrama de Componentes

NutriVigilancia está estructurada en tres capas principales que se comunican mediante una API REST con autenticación JWT.

La **capa de presentación** es una aplicación de página única (SPA) desarrollada con React 18 y Vite, desplegada en Vercel. Organiza la interfaz en tres paneles según el rol del usuario. El **panel clínico (CLI)** permite el registro de pacientes, la captura de controles antropométricos, la consulta de alertas tempranas y el uso del asistente de voz NIVI. El **panel analítico (ANL)** está dedicado exclusivamente a la visualización epidemiológica y la generación de reportes: incluye dashboards con indicadores y gráficos, integración con Power BI y la exportación de reportes nutricionales, epidemiológicos y de pacientes en Excel con análisis mediante IA; no tiene acceso a la gestión del sistema. El **panel administrador (ADM)** concentra toda la administración operativa: gestión de usuarios, carga y habilitación de datasets SIVIGILA, configuración y lanzamiento de jobs de entrenamiento de modelos ML, activación de modelos en producción y generación del reporte exclusivo de modelos con sus métricas y comparativas. Un contexto global de autenticación y un cliente HTTP centralizado (Axios) gestionan la sesión y la comunicación con el servidor en todos los paneles.

La **capa de negocio** es una API REST construida con FastAPI (Python 3.11) y contenedorizada en Docker para su despliegue en Google Cloud Run. Expone 13 grupos de endpoints organizados por dominio funcional. Al iniciarse, carga en memoria los modelos de machine learning entrenados para garantizar baja latencia en cada predicción. El módulo ML interno aplica tablas de referencia de la OMS, codificación de variables, imputación y escalado antes de clasificar el estado nutricional del menor en seis categorías. Para las funciones de inteligencia artificial, el sistema se conecta con Google Gemini (recomendaciones clínicas personalizadas y análisis de reportes) y con Groq Llama 3.3 (asistente clínico de voz NIVI y análisis epidemiológico del dashboard).

La **capa de datos** reside en Supabase (PostgreSQL) con seis tablas: perfiles de usuario, pacientes, controles clínicos, alertas, modelos ML y datasets de entrenamiento. Los datos históricos provienen de archivos Excel del sistema SIVIGILA procesados mediante un pipeline ETL que unifica, limpia e imputa los registros de desnutrición aguda de los años 2020 a 2025. Los modelos predictivos fueron desarrollados en siete notebooks de Jupyter y exportados como artefactos `.joblib` que el backend consume en producción.
